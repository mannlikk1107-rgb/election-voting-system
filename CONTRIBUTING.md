# Contributing Guide

This project is developed by a university team of nine members. Please follow these team standards when contributing.

## Branch naming

- feature/feature-name
- fix/issue-name
- test/test-name
- docs/document-name

## Commit examples

- feat: add election creation form
- fix: prevent duplicate voting
- test: add voter eligibility tests
- docs: update Render deployment guide

## Pull request requirements

- Explain the feature or fix included in the PR.
- Include screenshots for interface changes.
- Include test evidence.
- Do not merge when tests fail.
- Require at least one teammate review.
- Resolve merge conflicts before approval.
- Never commit secrets or real voter information.

## Workflow

1. Create a branch using the naming convention.
2. Keep changes focused and reviewable.
3. Update or add tests for relevant behavior.
4. Run the project validation check.
5. Open a PR with clear summary and evidence.
